# froD — Architecture

## Guiding principles
1. **Zero dependencies.** Everything is the web platform + Node's standard library.
2. **Logic ≠ presentation.** The simulation runs identically in Node and the browser.
3. **Determinism where it matters.** Daily challenges and level layouts are seeded.
4. **Procedural assets.** Art and audio are generated, not shipped as binaries.

## The simulation core (`src/game/`)

### Grid & rows
The board is 13 columns × 13 rows. Row kinds:
- `0` goal (hedges + 5 home bays at x = 0, 3, 6, 9, 12)
- `1–5` river (logs / turtle groups)
- `6` median (safe, spawns pickups)
- `7–11` road (cars, taxis, trucks, buses, one fast lane)
- `12` start (safe)

### Conveyors
Each road/river lane is a looping pattern of items. `level.js` builds a pattern
longer than the screen plus margins, then `world.js` advances every item by
`dir * speed * dt` and wraps it by the exact pattern `span`. Gaps are constrained:
- road gaps ≥ `1.7 + speed * 0.45` cells → always crossable at that speed;
- river gaps ≤ `3.2` cells → a waiting frog can always find a ride.

### Coordinate convention
Grid-centered entities (frog, bays, pickups) use `pixel = coord * 16` for the
sprite top-left, so the frog's center is `coord*16 + 8`. Continuous entities
(vehicles, logs, turtles) use `pixelLeft = coord*16 + 8`. This makes the
collision test (`item.x < frog.x + half && item.x + len > frog.x - half`)
match the visuals exactly.

### Frog lifecycle
`hop(dir)` starts a 0.13s tween; input during a hop is buffered and chained on
landing. On landing the world resolves the row: goal → home/death, river →
attach to a platform or drown, road → collision check. While idle on a river the
frog drifts with its platform and re-checks support (diving turtles, edges).

### Difficulty & themes
Speed multipliers scale with level (capped), gaps tighten slightly, and the time
limit shrinks from 60s toward 35s. Themes cycle day → dusk → night → dawn.

## Game flow (`game.js`)
A state machine: `menu → playing ⇄ (dying | scored | clear) → over | dailyComplete`.
The `Game` owns score/lives/level/mode and re-emits world events. Extra lives are
granted every 10,000 points (capped at 6). Daily mode ends after 5 levels.

## Presentation
- **sprites.js** bakes pixel maps + tiny drawing routines into offscreen canvases,
  once per theme. Palettes derive from one base via color mixing.
- **renderer.js** composes background, platforms, vehicles, pickups, frog (with
  hop arc, squash/stretch, shield ring, death animations), lights and fireflies.
- **audio.js** synthesizes SFX from oscillators/noise and sequences a 64-step
  chip loop (Am–F–C–G) with a look-ahead scheduler. Night/dusk transpose it down.
- **particles.js** is a pooled pixel particle system with shake + flash.

## Wiring (`main.js`)
A fixed-timestep loop (60 Hz, accumulator + max-step clamp) drives the world.
Game events fan out to audio, FX, HUD, meta and toasts. The menu runs a live
autopilot demo. Settings, language and persistence are applied centrally.

## Testing strategy
- **Unit**: rng, level invariants (gap bounds, determinism, difficulty scaling),
  world mechanics (collisions, rides, dives, pickups, timer), game flow, meta.
- **Autopilot/solvability**: a heuristic bot must reach homes and fully clear a
  level — evidence that generation never produces impossible layouts.
- **Integration smoke**: boots the real `main.js` against a DOM shim and drives
  frames, input, pause/resume and language switching.
- **Visual**: `scripts/screenshot.mjs` runs the real renderer through a software
  canvas to emit PNGs, so art regressions are visible in review.

## Offline / PWA
A network-first service worker caches the shell and assets, falling back to cache
when offline. Icons are generated by `scripts/gen-icons.mjs` (hand-rolled PNG
encoder). The manifest declares standalone, portrait, RTL.
